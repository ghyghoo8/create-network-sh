# G8 网关后台启停脚本

适用当前 Ubuntu 部署。将 `start.sh` 和 `stop.sh` 放在
`/opt/gitee-mcp-gateway/gateway`，与 `gateway_server.py`、`gitee_repository_tools.py`、`auth_policy.py` 和已填写的 `.env` 同目录。

用之前配置 ngrok 的同一个 SSH 账户运行。脚本默认使用
`/opt/gitee-mcp-gateway/.venv/bin/python`，以及该账户 PATH 中的 `ngrok`。
依赖 Bash、Python、GNU coreutils 和 util-linux（`setsid`、`flock`），Ubuntu 通常已有。

## 首次切换

在原 gateway 和 ngrok 的两个前台终端分别按 Ctrl+C。
然后上传脚本并执行：

```bash
cd /opt/gitee-mcp-gateway/gateway
chmod 755 start.sh stop.sh
./start.sh
```

网关的无认证 `/mcp` 返回 401 后才启动 ngrok。
ngrok 保留现有固定域名、`--inspect=false`，并开启 info 级逐行 JSON 运行日志。
脚本检查两个进程存活；实际隧道连接状态见 ngrok 日志中的连接或报错信息。

启动成功后可关闭 SSH。重复运行 `./start.sh` 会复用已核验的进程。

## 停止与重新启动

```bash
cd /opt/gitee-mcp-gateway/gateway
./stop.sh
./start.sh
```

停止顺序为 ngrok → gateway。先发 TERM，默认等 8 秒，
仍未退出时再次校验进程身份，再发 KILL。停止后保留日志。
重复停止可正常执行。脚本核对 PID、启动时间、启动批次所在系统 boot ID、
用户以及进程组/会话，过期记录会归档，格式异常则报错。

首次运行若 8765 已被手动启动的网关占用，脚本会提示先在其原终端停止。
脚本只管理自己的 `run/*.pid` 记录，不接管前台旧实例。

## 查看日志

```bash
cd /opt/gitee-mcp-gateway/gateway
tail -n 100 logs/control.log
tail -F logs/gateway.latest.log
tail -F logs/ngrok.latest.log
```

每条 `tail -F` 可在单独终端执行，Ctrl+C 只结束日志查看。

| 文件 | 内容 |
| --- | --- |
| `logs/control.log` | UTC 时间、运行 ID、启动/停止请求、PID、就绪检查、重复操作、失败和清理结果 |
| `logs/gateway-日期-随机码.log` | 此次网关 stdout/stderr；现有网关的启动提示及安全错误信息 |
| `logs/ngrok-日期-随机码.log` | 此次 ngrok stdout/stderr，含 info 级 JSON 运行日志 |
| `logs/gateway.latest.log` | 指向最近一次网关运行日志 |
| `logs/ngrok.latest.log` | 指向最近一次 ngrok 运行日志 |
| `run/gateway.pid`、`run/ngrok.pid` | 受控进程元数据 |
| `run/*.pid.stale.*` | 过期进程记录，保留用于排查 |

日志范围是服务生命周期和进程输出。沿用网关对 OAuth 参数与请求正文的日志限制，
不增加逐次 MCP 操作审计。日志目录、运行目录权限为 700，日志与进程记录为 600。
历史日志不自动覆盖或删除，时间统一为 UTC（北京时间加 8 小时）。

## 运行边界

- SSH 断开后继续运行；服务器重启后需重新执行 `./start.sh`。
- 这套脚本不设置开机自启或进程退出后的自动拉起。
- 当前 OAuth 使用内存状态，每次 gateway 真正重启后，需要重新连接 ChatGPT 插件。
  重复 start 复用既有进程时不重启 gateway。
- 启动失败会清理本次启动的进程，保留此前已在运行的受控进程和故障日志。
- 令牌继续由服务器现有 `.env` 读取，脚本不 source 它、不输出其内容。

## 离线验证

使用模拟的 HTTP 401 网关和 ngrok 进程验证启动、停止、重复操作、
并发锁、启动失败清理、PID 过期保护及日志权限。
未连接真实 Gitee/ngrok，也未在你的服务器执行。
